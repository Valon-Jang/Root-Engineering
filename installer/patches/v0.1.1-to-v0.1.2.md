# Patch 0.1.1 → 0.1.2: Runtime-Aware Model Recommendation

## Preconditions

- Read both Manifests and require Package ID `root-engineering-chat-installer` and Package Version `0.1.1` in both.
- Require one unambiguous Project Binding and readable Global Protocol and Project Instructions.
- If either version differs, stop without mutation.

## Operations

In the existing Global Protocol and Project Instructions, replace any fixed model recommendation or older model-routing block with one `Model Recommendation Adapter` implementing all rules below. Preserve document IDs and all unrelated sections.

### Required adapter

- Re-evaluate every substantive task and recommend the smallest sufficient **actual model plus reasoning effort** available in the current runtime.
- Treat model tier and reasoning effort as separate axes.
- Inspect the product surface immediately before recommending; never claim an unavailable option is selectable.
- Candidate order is `GPT-5.6 Terra → GPT-5.6 Sol → GPT-5.6 Sol Pro`. Do not recommend GPT-5.6 Luna.
- If Terra is not selectable in standard ChatGPT, translate the intent to the closest selectable Sol setting.
- Use five routing dimensions: task complexity, ambiguity, consequence of error, context/tool coordination, and verification burden.
- Use Terra for mechanical through bounded work; use Sol for ambiguity, architecture, consequential decisions, broad context, or multi-tool work; use Sol Pro only when available and the highest quality materially changes the outcome.
- Do not escalate merely because a task is long and do not inherit the prior turn's recommendation automatically.
- For substantive work, print exactly one final line: `Recommended model for this task: <ACTUAL_MODEL> (<ACTUAL_REASONING_LEVEL>)`.
- Omit that line for greetings, casual chat, acknowledgements, and requests where model choice has no practical value.
- Do not expose internal routing labels such as `LIGHT`, `STANDARD`, `HIGH`, or `MAX` as the final recommendation.
- Treat model availability, UI labels, and reasoning levels as live runtime capability, not project knowledge to persist.

Remove the deprecated behaviors: fixed `GPT-5.6 Sol (High)` for all substantive tasks, a fixed Sol High template default, copied previous-turn recommendations, and Luna recommendations.

## Verification

Re-read the changed sections and test these cases mentally:

- a short rewrite routes below an architecture decision;
- a difficult multi-tool architecture task can route to Sol High or above when selectable;
- an unavailable Terra option is not presented as selectable;
- a greeting prints no recommendation line;
- exactly one recommendation line appears for substantive work.

Only after all checks pass, set Package Version to `0.1.2` in both Manifests and re-read both values. Keep Schema Version `0.1.0`.

## Failure

On any failed write, conflict, or verification, leave both Manifest versions at `0.1.1`, report the affected document, and stop. Do not continue to the next patch.
