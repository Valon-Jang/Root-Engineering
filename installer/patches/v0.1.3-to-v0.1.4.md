# Patch 0.1.3 → 0.1.4: Production-Quiet Communication

## Preconditions

- Require Package ID `root-engineering-chat-installer` and Package Version `0.1.3` in both Manifests.
- Require one unambiguous Project Binding and readable Global Protocol and Project Instructions.
- If either version differs, stop without mutation.

## Operations

Add one `Production Quiet Communication` section to the Global Protocol and Project Instructions. If a partial section exists, replace it rather than duplicating it.

After installation status is `ACTIVE`:

1. Perform routine project-record reads, writes, batching, and verification silently.
2. Do not announce successful internal processing such as updating storage, selecting a document, or flushing buffered changes.
3. Do not use `Root`, `Canonical`, `Branch`, `Node`, `Read Back`, `Save Gate`, `Root Update Buffer`, `flush`, or `persistence` in ordinary user-facing replies.
4. When the user explicitly asks to save or remember something, use plain language such as `Saved.` or `I saved that for future work.`
5. Do not add a storage-status sentence when it does not help complete the current task.
6. Do not hide a failed or uncertain update. Say plainly that the project record could not be updated and give the next useful action.
7. Technical terminology, IDs, revisions, and structure remain available for INSTALL, VERIFY, REPAIR, UPGRADE, diagnostics, explicit methodology or architecture discussion, and direct requests to inspect the internal structure.
8. These communication rules do not weaken authority, Save Gate, write, verification, conflict, or recovery behavior.

## Verification

- An ordinary successful background update produces no storage-status sentence.
- An explicit save request receives a short plain-language acknowledgement.
- A failed update remains visible and actionable.
- A diagnostic request can still expose the required technical details.
- The protected terms do not appear in a simulated ordinary user-facing reply.

Only after all checks pass, set Package Version to `0.1.4` in both Manifests and re-read both values. Keep Schema Version `0.1.0`.

## Failure

On failure, leave both Manifest versions at `0.1.3`, identify the failed scope in diagnostic language, and stop.
