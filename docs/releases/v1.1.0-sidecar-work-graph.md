# Root Engineering 1.1.0 — Sidecar Work Graph

**Status:** Staged next version  
**Base:** Root Engineering 1.0.0 Rebirth  
**Release date:** 2026-09-04

## Summary

Root Engineering 1.1.0 adds a non-destructive topology for projects that already contain a mature Markdown corpus.

Instead of rewriting legacy files into a new template, the release creates a `.root/` control plane beside the existing content, registers every Markdown owner in place, and verifies byte preservation with pre/post SHA-256.

## Main additions

- Sidecar workspace topology under `.root/`
- Control plane / content plane separation
- `CONTENT_REGISTRY.json` with stable node roles and hashes
- Root → Routing Core → exact Work Context lookup
- Explicit role separation:
  - Operating Profile
  - Routing Core
  - Execution Standard
  - Work Context
  - Handoff
  - Reference
- Fail-closed adoption when any protected Markdown path, size, or hash changes
- Reference CLI and CI self-test

## Preservation guarantee

During structural adoption, existing Markdown files are not:

- edited;
- moved;
- renamed;
- deleted;
- merged;
- re-encoded;
- or line-ending normalized.

Only Root-owned files under `.root/` are created or patched.

## Compatibility

Rebirth 1.0.0 remains the Kernel baseline. The isolated `/mnt/data/root-engineering/` topology remains valid for new projects. Sidecar mode is recommended when a project workspace already contains authoritative files that must remain unchanged.

## Promotion gate

Promote only after:

1. repository validation passes;
2. the reference self-test confirms byte-exact preservation;
3. the pull-request diff confirms no pre-existing Markdown file was modified;
4. routing resolves an exact work node without scanning unrelated work files.
