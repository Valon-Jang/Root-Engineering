# Root Engineering 1.0.0 — Rebirth

Release date: 2026-09-04

## Major change

Root Engineering now treats **active conversation context** as replaceable working memory in addition to treating the model as replaceable.

> **Model is replaceable. Context is replaceable. Root persists.**

The release version remains `1.0.0`. The compact-time backup policy below is a clarified operating contract, not a version change.

## Complete Chat Runtime

Rebirth frames the ordinary ChatGPT surface as an independent **Complete Chat Runtime** — the “완성형 Chat” concept for long-running projects:

```text
human-visible transcript
+ replaceable active context
+ Local ROOT
+ resumable CHECKPOINT
+ optional compact-time recovery mirror
```

This is Root Engineering terminology, not an official OpenAI feature or a custom API/CLI chat client.

## New default ChatGPT runtime

- Ordinary ChatGPT Chat; Project not required.
- Chat-local writable workspace, preferring `/mnt/data` when exposed.
- Google Drive no longer required for normal Chat-native operation.
- Local Root is the primary current-runtime store.
- Drive/Git/export become optional backup, migration, collaboration, and recovery adapters.

## New first-class runtime owner

`runtime/CHECKPOINT.md` stores immediate resume state separately from durable project knowledge.

This prevents transient progress from polluting the Root while allowing work to continue after active-context reduction.

## Rebirth compaction transaction

```text
Persist durable state
→ Refresh CHECKPOINT
→ Verify and seal local state
→ Synchronize external recovery mirror if configured
→ Compact active context
→ Verify compaction
→ Increment context epoch
→ Rehydrate minimal state
→ Continue same Chat
```

Hard invariant:

> **SAVE FAILURE = NO COMPACT**

## Compact-time backup policy

External backup synchronization now has one default trigger:

> **Explicit `압축해` / `compact` maintenance only.**

- Scheduled backup sync: disabled.
- Idle/background backup sync: disabled.
- An explicit standalone `backup` command remains allowed.
- Local state is persisted and sealed before any external backup tool boundary.
- A configured adapter updates a verified `latest` recovery mirror; unchanged snapshot hashes may skip the remote write.
- Optional backup failure is recorded as pending and reported, never silently treated as success.
- A strict `backup and compact` request may require external verification before compaction.
- If the backup tool call itself triggers confirmed host compaction, Rebirth uses that event and does not emit a second trigger.

This keeps connector latency out of ordinary active work and avoids assuming that a separately scheduled runtime can access the same chat-local `/mnt/data`.

## Compaction capability policy

1. use a native compact action only when the host actually exposes/supports it;
2. otherwise use a zero-output boundary only when the same environment has already verified that behavior and success can be confirmed;
3. bounded pressure is diagnostic-only and stops immediately on success.

No private/internal compaction RPC is invented or assumed.

## Validation included

- `tools/validate_rebirth_installer.py`
- `tools/rebirth_local_selftest.py`
- `tools/validate_rebirth_runtime.py`

Local release tests cover:

- required Local Root file creation;
- identity consistency;
- atomic write/read-back path;
- independent Checkpoint refresh;
- save-failure compaction guard;
- compact-time external-backup status recording;
- scheduled/idle sync rejection;
- context epoch increment only after simulated compaction confirmation.

## Compatibility

Existing adapters remain available:

- ChatGPT Project + Google Drive v0.1.12
- Codex project-local Root
- Claude + Google Drive Root

The old ChatGPT Drive installer is retained as a legacy/external adapter rather than deleted.

## Research basis

The separate `Valon-Jang/persistent-project-thread` experiment supplied the ChatGPT-specific compaction observations that motivated the Rebirth runtime model. Those observations are explicitly environment-specific and are not presented as universal guarantees about private ChatGPT internals.

## Open benchmark target

Repeated real compaction cycles in one long-lived Chat remain the next major benchmark:

```text
work → save → checkpoint → backup → compact → rehydrate → continue
```

Measure state accuracy, resume accuracy, decision retention, external-recovery correctness, no-repeat behavior, latency/context trend where observable, and quality degradation across context epochs.
